## 1. Resumen Ejecutivo

Durante la presente misión de aseguramiento de la calidad (QA), se ejecutó una investigación dirigida y forense sobre el script `start-tv-kiosk.ps1`, la simulación y emparejamiento de televisores, la reconciliación de versiones entre el repositorio Git y los contenedores Docker en tiempo de ejecución, y una auditoría integral de seguridad, operabilidad, reproducción y despliegue.

### Conclusiones Principales:
1. **Fallo Crítico Demostrado en `start-tv-kiosk.ps1` (BUG-006 / P0):**
   El script no puede ejecutarse en sistemas Windows con PowerShell 5.1 debido a un fallo sintáctico fatal (`ParserError: AmpersandNotAllowed`). El archivo fue codificado en UTF-8 sin BOM conteniendo caracteres em-dash (`—`), los cuales PowerShell 5.1 interpreta en Windows-1252 como comillas de cierre prematuras (`”`), dejando texto sin entrecomillar con el operador reservado `&`. El navegador nunca llega a ser invocado.
2. **Defecto de Simulación de TV Nueva (BUG-007 / P1):**
   El script fuerza el uso de un directorio de perfil fijo `$env:TEMP\nexus_tv_kiosk_profile`. Si dicho perfil fue utilizado anteriormente, rescata el `tv_uuid` persistido en `localStorage` de Chromium, omitiendo por completo la pantalla de bienvenida con PIN `#xxxx` e impidiendo simular una televisión nueva.
3. **Reconciliación de Versiones Conforme:**
   Se verificó criptográficamente que los contenedores Docker (`tv-backend`, `tv-db`, `tv-frontend`) están ejecutando exactamente el código correspondiente al commit local y remoto `d346408` (release v2.1.3). No existen desfases entre el código local y los contenedores.
4. **Estado Real de BUG-001 a BUG-005:**
   Se revalidó en el código en ejecución que los bugs históricos `BUG-001` (discriminación horaria), `BUG-002` (inconsistencia de 24 archivos 404 y bucle acelerado de imagen), `BUG-003` (layout sin `@media`), `BUG-004` (tildes en días) y `BUG-005` (JWT en `/api/admin`) se encuentran **efectivamente mitigados** en esta compilación.
5. **Nuevos Hallazgos Críticos de Seguridad y Operaciones:**
   Se descubrió que la API administrativa carece de control de acceso por roles (RBAC) permitiendo a usuarios con rol `viewer` ejecutar borrados y control remoto (BUG-008), la Opción 6 de `run-local.ps1` destruye la base de datos con `down -v` (BUG-009), y `run-local.ps1` copia claves inseguras por defecto desde `.env.example` (BUG-010).

## 3. Diagnóstico Forense de `start-tv-kiosk.ps1`

### 3.1. Condiciones del Entorno Windows
- **Motor PowerShell:** Versión 5.1.19041.6456.
- **Política de Ejecución:** `Restricted` efectiva por defecto en todos los ámbitos.
- **Navegadores Físicos:** Google Chrome (`C:\Program Files\Google\Chrome\Application\chrome.exe`) y Microsoft Edge (`C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`) instalados y operativos.
- **Servicios:** Docker activo; `http://localhost:23002/api/status` responde 200 OK; `http://localhost:28080/tv` responde 200 OK.

### 3.2. Error Exacto Capturado y Cadena de Fallo
Al invocar `powershell.exe -ExecutionPolicy Bypass -File .\start-tv-kiosk.ps1`, el analizador aborta con código 1:
```text
En C:\Users\DEVELOPMENT\Downloads\tv_gsi\start-tv-kiosk.ps1: 17 Carácter: 44
+ Write-Host "    NEXUS TV —" KIOSK DISPLAY & AUDIO AUTO-UNLOCK     "  ...
+                                            ~
No se permite usar el carácter de Y comercial (&). El operador & está reservado para un uso futuro; encierre un
símbolo de Y comercial entre comillas dobles ("&") para pasarlo como parte de una cadena.
    + CategoryInfo          : ParserError: (:) [], ParentContainsErrorRecordException
    + FullyQualifiedErrorId : AmpersandNotAllowed
```

### 3.3. Causa Raíz Demostrada (RCA)
1. El archivo carece de BOM UTF-8. PowerShell 5.1 lee el archivo bajo ANSI/Windows-1252.
2. El carácter em-dash (`—`, bytes `0xE2 0x80 0x94`) en la línea 17 contiene el byte `0x94`, que en Windows-1252 equivale a la comilla tipográfica `”` (U+201D).
3. En la sintaxis de PowerShell, `”` actúa como delimitador de cierre de cadena, cerrando la comilla de `Write-Host "`.
4. El texto subsiguiente `KIOSK DISPLAY & AUDIO AUTO-UNLOCK` queda expuesto como código fuera de comillas, provocando que el operador `&` dispare la excepción `AmpersandNotAllowed`.
5. **Impacto:** Ningún comando ni navegador es ejecutado jamás.

### 3.4. Análisis de Escenarios de Red
- **Escenario A (Mismo Ordenador):** El destino `http://localhost:28080/tv` es válido localmente, pero está bloqueado por el error sintáctico y la retención del perfil persistente.
- **Escenario B (Dispositivo / Smart TV en LAN):**
  - Si se ejecuta el script en un dispositivo remoto, el valor por defecto `TargetUrl = "http://localhost:28080/tv"` apunta a la propia pantalla remota, arrojando `ERR_CONNECTION_REFUSED`.
  - Si se pasa `-TargetUrl "http://<IP_DOCKER>:28080/tv"`, las conexiones WebSocket y API son **bloqueadas por política CORS** en `nx_tv.js` debido a que `ALLOWED_ORIGINS` solo permite `localhost` y `127.0.0.1`.

## 6. Auditoría Técnica por Dominios Especializados

### 6.1. Pairing y Sesiones Zero-Touch
- **Colisiones de PIN:** El PIN de sesión se genera como un entero aleatorio de 4 dígitos (`1000` a `9999`, 9,000 combinaciones) en `TVPlayer.jsx` (L31). En una implementación con múltiples pantallas simultáneas en espera, existe probabilidad de colisión de PIN. Si dos pantallas toman el mismo PIN, ambas se unen a la misma sala `session:PIN`. Al asignar un perfil, **ambas pantallas adoptan el mismo `tv_uuid`**, y solo una es eliminada de `waitingScreens`, dejando la otra huérfana.
- **Desconexión durante Asignación:** En `src/routes/admin.js` (L86-90), se valida que el `sessionCode` exista en `waitingScreensMap`. Si el cliente se desconecta justo antes de la asignación, la API responde 404 de forma segura.

### 6.2. WebSockets y Control Remoto
- **Mapeo de Clientes Conectados:** `onlineScreens` utiliza un `Map` donde la clave es `tv_uuid` y el valor es `socket.id` (relación 1:1). Si un usuario abre dos pestañas de la misma TV y cierra una de ellas, el evento `disconnect` ejecuta `onlineScreens.delete(tvUuid)` y notifica a los administradores que la pantalla está offline, a pesar de que la segunda pestaña continúa conectada y reproduciendo. Se recomienda usar una estructura `Map<tv_uuid, Set<socketId>>`.
- **Telemetría y Latidos:** La TV emite latidos cada 15 segundos tanto por HTTP (`/api/tv/heartbeat`) como por WebSocket (`tv:heartbeat`), informando volumen, título actual, estado de override y estado de desbloqueo de audio.

### 6.3. Seguridad y Configuración (ISO/IEC 27001)
- **Gestión de Secretos:** `docker-compose.yml` utiliza `${JWT_SECRET:?Set JWT_SECRET in .env}` para impedir arrancar sin variable. Sin embargo, este control es evadido por la copia desatendida de `.env.example` en `run-local.ps1`.
- **Superficie de Exposición de Puertos:** Los puertos `25432` (PostgreSQL), `23002` (Backend) y `28080` (Frontend) están expuestos en el host (`0.0.0.0`). En un entorno corporativo, el puerto de PostgreSQL `25432` no debería estar expuesto públicamente en todas las interfaces de red del host, sino restringido a `127.0.0.1:25432` o cerrado al exterior.

### 6.4. Despliegue y Operaciones (ISO 9001 / ISO/IEC 25010)
- **Persistencia de Base de Datos:** El volumen `tv_pgdata` persiste adecuadamente los datos en reinicios estándar (`docker compose restart` o `docker compose down` sin `-v`). La vulnerabilidad reside exclusivamente en la Opción 6 de `run-local.ps1`.
- **Aislamiento de Tests E2E:** `scripts/e2e_full_audit.cjs` interactúa con la base de datos real y emite a salas globales (`target: all`). Por estricto mandato de la Regla 0, su ejecución fue **BLOQUEADA** para preservar la integridad operativa del sistema y evitar interferir con pantallas reales.

## 8. Próximos Cinco Casos de Prueba Prioritarios

Conforme a la metodología ISO/IEC 29119 y estándar Dev Team v1.0, los siguientes casos deben ejecutarse una vez corregidos los defectos bloqueantes:

1. **TC-RETEST-KIOSK-001 (P0):** Retest de compilación y arranque de `start-tv-kiosk.ps1` con codificación ASCII pura y flag de perfil limpio (`-CleanSession`).
2. **TC-RETEST-RBAC-001 (P0):** Validación de denegación HTTP 403 Forbidden para usuarios con rol `viewer` en endpoints destructivos (`DELETE /api/admin/screens/:uuid`, `/api/admin/playlists/:id`).
3. **TC-SECURITY-WS-001 (P1):** Prueba de rechazo de conexiones WebSocket al namespace `/control` que utilicen `tv_uuid` no firmado o sin token de pantalla.
4. **TC-NETWORK-LAN-001 (P1):** Prueba de acceso y reproducción desde una pantalla física en red local corporativa a través de la IP del host Docker con `ALLOWED_ORIGINS` configurado.
5. **TC-DEVOPS-DOWN-001 (P1):** Verificación de parada limpia del stack local con `run-local.ps1` asegurando la preservación del volumen PostgreSQL `tv_pgdata` al 100%.
