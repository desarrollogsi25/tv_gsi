## 3. Evidencias Técnicas

### 3.1. Ausencia de Parámetro y Normalización en Frontend
* En `ContentManager.jsx` (L158-162):
  ```javascript
  await axios.post(`${API_URL}/api/admin/playlists/${selectedPlaylistId}/items`, {
      content_id: parseInt(addItemContentId, 10),
      start_time: addStartTime,
      end_time: addEndTime
  });
  ```
* El formulario no ofrece selección de días al operador y no envía `days_of_week`, mientras que en la visualización de la tabla (L449) asume estáticamente `Lun - Dom`.

### 3.2. Ausencia de Sanitización en Backend Administrativo (`src/routes/admin.js`)
```javascript
const defaultDays = ['lunes', 'martes', 'miércoles', 'jueves', 'viernes', 'sábado', 'domingo'];
const days = (Array.isArray(days_of_week) && days_of_week.length > 0) ? days_of_week : defaultDays;
```
* Si la petición proviene de una integración, script o llamada de API externa que envíe `days_of_week`, **el backend inserta el array directamente en la base de datos sin sanitizar, limpiar acentos ni validar ortografía**.

### 3.3. Colapso en Consulta de Playlists en la TV (`src/routes/tv.js`)
El motor de reproducción filtra los contenidos del día mediante:
```sql
AND pc.days_of_week @> ARRAY[
  CASE EXTRACT(ISODOW FROM CURRENT_DATE)
      WHEN 1 THEN 'lunes'
      WHEN 2 THEN 'martes'
      WHEN 3 THEN 'miércoles'
      WHEN 4 THEN 'jueves'
      WHEN 5 THEN 'viernes'
      WHEN 6 THEN 'sábado'
      WHEN 7 THEN 'domingo'
  END
]::text[]
```

### 3.4. Resultado de la Prueba SQL en `tv-db`
* `ARRAY['miercoles', 'sabado']::text[] @> ARRAY['miércoles']::text[]` $\rightarrow$ **`FALSE` (`f`)**.
* En PostgreSQL, `'miercoles'` no es igual a `'miércoles'`.
* **Consecuencia Inequívoca:** Si un operador o sistema externo programa un contenido indicando `["lunes", "miercoles", "viernes"]` (sin tilde en miércoles), el día miércoles el motor de TV evaluará la cláusula como `false`, **y la pantalla NUNCA proyectará dicho contenido en todo el día**.

## 4. Conclusión y Clasificación

* **Clasificación:** ❌ **FALLO DE NORMALIZACIÓN DE DATOS (Bug Confirmado)**
* **Incidente Asociado:** **BUG-004** (`docs/11-incidents/bugs/BUG-004-unnormalized-days-accent.md`) / **RSK-016**.
* **Severidad:** **Media**
* **Prioridad:** **P1**
* **Justificación:** La falta de normalización (stripping de tildes o formateo canónico) en la capa de persistencia provoca que variaciones comunes de texto en días acentuados (`miércoles`, `sábado`) rompan silenciosamente la entrega de contenidos a las pantallas.
