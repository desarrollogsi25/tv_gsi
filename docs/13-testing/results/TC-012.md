## 4. Análisis Detallado de Implementación: AudioContext & Chime

### 4.1. Arquitectura del Sintetizador (`playChime`, L65-97)
```javascript
const playChime = () => {
    try {
        const AudioCtx = window.AudioContext || window.webkitAudioContext;
        if (!AudioCtx) return;
        if (!audioCtxRef.current) {
            audioCtxRef.current = new AudioCtx();
        }
        const ctx = audioCtxRef.current;
        if (ctx.state === 'suspended') {
            ctx.resume().catch(() => {});
        }
        const now = ctx.currentTime;
        const osc = ctx.createOscillator();
        const gain = ctx.createGain();

        osc.type = 'sine';
        osc.frequency.setValueAtTime(587.33, now); // Nota D5
        osc.frequency.exponentialRampToValueAtTime(880, now + 0.15); // Nota A5

        const vol = volumeLevel || 0.8;
        gain.gain.setValueAtTime(0.001, now);
        gain.gain.exponentialRampToValueAtTime(0.3 * vol, now + 0.05);
        gain.gain.exponentialRampToValueAtTime(0.001, now + 0.55);

        osc.connect(gain);
        gain.connect(ctx.destination);

        osc.start(now);
        osc.stop(now + 0.55);
    } catch (e) {
        console.warn('AudioContext chime warning:', e);
    }
};
```

### 4.2. Análisis de Riesgo: Políticas de Autoplay y Estado `suspended` (`RSK-013`)

1. **Comportamiento Asíncrono de `ctx.resume()`:**
   * La llamada `ctx.resume()` retorna una `Promise`. En la implementación actual, el código ejecuta inmediatamente de forma síncrona `const now = ctx.currentTime; osc.start(now); osc.stop(now + 0.55);`.
   * Si el contexto se encuentra en estado `'suspended'`, su propiedad `currentTime` se encuentra congelada en `0` o no avanza hasta que la reanudación es concedida por el motor de audio del navegador.
2. **Bloqueo de Autoplay por Navegadores Modernos (Chrome / Edge / Chromium Kiosk):**
   * Según la especificación W3C Web Audio API y las políticas de autoplay de Chromium, un `AudioContext` no puede emitir sonido ni reanudarse (`resume()`) sin una interacción previa del usuario (User Gesture: `click`, `keydown`, `touchstart`).
   * Debido a que el comando de campanilla o volumen llega a través de un evento de red push (WebSocket), **no existe un User Gesture activo** en el hilo principal del DOM.
   * Consecuencia: Chromium rechaza la promesa devuelta por `ctx.resume()` con una excepción `NotAllowedError: The AudioContext was not allowed to start. It must be resumed (or created) after a user gesture on the page.`.
3. **Manejo Actual en `TVPlayer.jsx`:**
   * La excepción es capturada silenciosamente mediante `.catch(() => {})`.
   * **Impacto Operativo:** La aplicación no crashea ni muestra alertas en pantalla, pero **el sonido de la campanilla no se escuchará físicamente** en una pantalla de señalización desatendida recién encendida o recargada.
4. **Condición de Mitigación Actual en `start-tv-kiosk.ps1`:**
   * Si el modo Kiosk se ejecuta mediante Chromium/Edge con el flag `--autoplay-policy=no-user-gesture-required`, el navegador exime la página de esta restricción y el sintetizador suena de forma transparente.
   * En navegadores estándar de prueba o smart TVs sin dicho flag, se requiere un clic manual en pantalla o desbloqueo inicial.
