Existen turnos definidos explícitamente en la base de datos:
* Turno Mañana: `06:00:00 - 08:59:00` (15 contenidos)
* Turno Mediodía: `09:00:00 - 11:59:00` (15 contenidos)
* Turno Tarde: `12:00:00 - 15:59:00` (15 contenidos)

### 3.2. Inspección del Código SQL (`src/routes/tv.js`, L70-100)
```sql
SELECT c.id AS content_id, c.title, c.source_url, c.source_type, c.content_type, 
       c.duration_seconds, pc.start_time, pc.end_time, pc.days_of_week
FROM nexus_tv.tv_screens AS ts
JOIN nexus_tv.tv_playlist AS tp ON ts.id = tp.tv_id
JOIN nexus_tv.playlists AS p ON tp.playlist_id = p.id
JOIN nexus_tv.playlist_content AS pc ON p.id = pc.playlist_id
JOIN nexus_tv.content AS c ON pc.content_id = c.id
WHERE ts.tv_uuid = $1
  AND ts.is_active = true
  AND pc.days_of_week @> ARRAY[ ... ]::text[]
ORDER BY pc.start_time ASC, c.id ASC;
```
**Hallazgo Crítico:** La consulta SQL filtra por el día de la semana (`pc.days_of_week @> ARRAY[...]`), pero **omite completamente cualquier condición de hora** (`start_time` y `end_time`).

### 3.3. Respuesta HTTP Obtenida
* **Total de Elementos Devueltos:** `45`
* **Desglose de Franjas en la Respuesta:**
  * `06:00:00 - 08:59:00`: 15 contenidos devueltos
  * `09:00:00 - 11:59:00`: 15 contenidos devueltos
  * `12:00:00 - 15:59:00`: 15 contenidos devueltos
* **Hora de Ejecución:** `18:31 CEST`. A pesar de que ninguno de los tres turnos corresponde a las 18:31, la API entregó la totalidad de los 45 contenidos del día.

## 4. Conclusión y Clasificación

* **Clasificación:** ❌ **FALLIDO (Bug Confirmado)**
* **Incidente Asociado:** **BUG-001** (`docs/11-incidents/bugs/BUG-001-schedule-ignored.md`).
* **Severidad:** **Alta**
* **Prioridad:** **P0**
* **Justificación:** La lógica del backend ignora las columnas `start_time` y `end_time`, y el reproductor cliente tampoco aplica filtrado de franja, provocando que los contenidos matutinos y de turnos disjuntos se reproduzcan indistintamente a lo largo de todo el día.
