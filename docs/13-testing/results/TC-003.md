# Resultado de Prueba: TC-003 — Discrepancia en Límite de Subida (Payload Mismatch)

> **Caso de Prueba:** TC-003  
> **Módulo:** Multimedia Engine / Upload Gateway & Reverse Proxy Configuration  
> **Fecha de Ejecución:** 2026-10-08  
> **Ejecutado por:** QA Lead & Senior Software Architect  
> **Entorno:** Local Docker (`tv-frontend` Nginx Reverse Proxy, `tv-backend` Node.js Express/Multer)  

---

## 1. Precondiciones
* Configuración de Nginx en `frontend/nginx.conf`.
* Configuración de middleware Multer en `src/routes/media.js`.

---

## 2. Pasos de Ejecución

1. **Inspección de Directivas Nginx:**  
   Se extrajo el valor de `client_max_body_size` en [frontend/nginx.conf](file:///c:/Users/DEVELOPMENT/Downloads/tv_gsi/frontend/nginx.conf).
2. **Inspección de Límites en Express / Multer:**  
   Se extrajo la directiva `fileSize` en [src/routes/media.js](file:///c:/Users/DEVELOPMENT/Downloads/tv_gsi/src/routes/media.js).
3. **Análisis de Conflicto de Configuración:**  
   Evaluación del flujo de paquetes HTTP multipart en la capa perimetral (Nginx) versus la capa de aplicación (Node.js).

---

## 3. Evidencias Técnicas

### 3.1. Valor en `frontend/nginx.conf`
```nginx
server {
    listen 8080;
    client_max_body_size 300M;
    ...
    location /api/ {
        proxy_pass http://backend:3002/api/;
        client_max_body_size 300M;
        ...
    }
}
```
* **Límite Perimetral Nginx:** **300 MB** (`300M`).

### 3.2. Valor en `src/routes/media.js`
```javascript
const upload = multer({
    storage,
    limits: { fileSize: 500 * 1024 * 1024 } // 500MB max
});
```
* **Límite de Aplicación Multer:** **500 MB** (`500 * 1024 * 1024` bytes).

### 3.3. Conflicto Detectado (Delta de 200 MB)
* Existe una discrepancia de **200 MB** entre la capa de entrada Nginx y el backend.
* **Comportamiento en Flujo de Subida (300 MB - 500 MB):**
  1. Si un usuario intenta subir un archivo de video de p.ej. 350 MB a través del panel de administración (`/admin/content`), la petición ingresa a Nginx en el puerto `8080` / `28080`.
  2. Nginx intercepta la carga en el buffer perimetral antes de reenviarla a Node.js.
  3. Al superar los 300 MB, Nginx aborta la conexión inmediatamente y devuelve una página de error HTML genérica con código **HTTP 413 Request Entity Too Large**.
  4. La petición **nunca llega a Node.js/Multer**, impidiendo que la aplicación devuelva una respuesta JSON estructurada (`{ success: false, message: ... }`) o reporte el error amigablemente en la interfaz web.

---

## 4. Conclusión y Clasificación

* **Clasificación:** ⚠️ **DISCREPANCIA CONFIRMADA (Riesgo de Configuración)**
* **Riesgo Asociado:** **RSK-015** (registrado en `docs/13-testing/risk-register.md`).
* **Severidad:** **Media**
* **Prioridad:** **P1**
* **Recomendación de Mitigación:** Alinear ambas capas al mismo umbral (establecer `client_max_body_size 500M;` en `frontend/nginx.conf` o reducir Multer a `300 * 1024 * 1024`).
