# Release v2.1.2 — Auditoría E2E y control remoto homologado

> **Fecha:** 2026-10-08
> **Tipo:** Reliability / Security / Admin workflows
> **Rama:** `fix/NX-014-full-system-e2e-audit-and-remote-control`
> **Estado:** Validación local completada; listo para integrar en `staging`.

## Cambios

- Homologados los comandos `pause`, `resume`, `skip`, `reload`, `mute`, `unmute`, `chime` y `set_volume` entre la consola, Socket.IO y `TVPlayer`.
- Las TVs se registran en `screen_<uuid>` y conservan compatibilidad con la sala `tv:<uuid>`. Los sockets administrativos requieren Bearer JWT con rol `admin`; CORS de Socket.IO usa los orígenes permitidos.
- El reproductor conserva el tiempo restante al pausar; reconoce alias de medios, controla YouTube embebido y mantiene autoplay de video silenciado/inline.
- Añadidas acciones para rechazar PINs pendientes y editar, desvincular o eliminar perfiles de pantallas. Las operaciones de actualización/eliminación de playlists y pantallas usan transacciones.
- Añadido CRUD de playlist (renombrar, eliminar, añadir/quitar y ordenar elementos), selección de días, horarios opcionales 24/7 y notificación de actualización a las pantallas asignadas.
- La interfaz permite subir hasta 500 MB, coherente con Nginx y Multer. El límite de subida se validó con una petición de 100 MiB a través de Nginx.
- Añadidas migraciones `03_playlist_ordering.sql` y `04_sync_screen_id_sequence.sql`. La última repara la secuencia desfasada de IDs de pantalla detectada en la base operativa.
- `JWT_SECRET` y `PG_PASSWORD` son obligatorios en producción; se documentan en `.env.example` y se mantienen fuera del repositorio.

- `npm test`: **13/13 PASS**.

- `npm run build`: **PASS**. El runtime local Node 20.18 muestra el aviso de Vite que recomienda Node 20.19+.
- `node scripts/e2e_full_audit.cjs`: **8/8 grupos PASS** por Nginx, incluyendo login/401, socket admin autenticado, 8 comandos, pausa global, emisión temporal dirigida/global y limpieza, pairing, CRUD de pantallas, subida PNG/JPG/MP4 y MP4 de 100 MiB, playlist con días/horarios/reordenamiento/24-7 y borrado.
- Los recursos creados por el E2E se eliminaron al finalizar. Se corrigió la secuencia de `tv_screens` después de que la primera ejecución revelara que su valor era menor que `MAX(id)`.
- `docker compose build frontend backend` y `docker compose up -d frontend backend`: **PASS**; backend y frontend saludables, `GET /api/status` responde online y Nginx responde HTTP 200 en `28080`.
- Se escanearon los componentes frontend: no quedan llamadas a `window.alert()` ni `window.confirm()`.

## Alcance de la evidencia

El E2E ejercita HTTP, Nginx, Socket.IO y PostgreSQL. Las verificaciones de pausa/reanudación, recarga y audio confirman el envío y recepción de eventos y la ruta de código; no instrumentan el frame real de una Smart TV ni miden la salida acústica. Por eso esos tres casos permanecen marcados como parciales en la matriz hasta una inspección visual/física del dispositivo.
